# Rendering experiment findings — 2026-10-12

The experiment expanded beyond the intended small check. Its source, test drivers,
build configuration and README are preserved as an experimental snapshot on
`spike/rendering`, at the user's request. They are not an accepted application
implementation. Further code work is stopped pending agreement on structure,
engineering rules and phase scope. This report is separate from the design blueprint.

Experimental source snapshot: `2674f63`.

Subsequent clarification: the user accepts further API exploration under the
50-line/checkpoint rules in [AGENTS.md](../../../../../qvu/AGENTS.md). Production implementation
and optimization remain separate; the snapshots below are exploratory measurements.

| Finding | Consequence |

These observations support another tightly bounded phase after structure/rules are
agreed. They do not validate the whole application or justify extending the prototype.

## Observed results

- **Build/Wayland:** the probe built with the installed packages and opened through
  Wayland with app-id `qvu-render-probe`. Runtime versions: Qt 6.12.0 and WebEngine
  6.11.2. No engine rebuild was needed for this check.
- **Markdown:** HTML generated by the existing Neovim renderer worked over loopback
  HTTP: two KaTeX equations, zero reported math errors, a GFM table/task list, and a
  480-pixel-wide local SVG with a percent-encoded space in its filename. Visual
  inspection confirmed the equations, table and image.
- **Local-file caveat:** the same fixture initially showed raw math through
  `file://`, with KaTeX unavailable. Its CDN URL returned HTTP 200, and the HTTP
  preview rendered correctly. This supports retaining the existing HTTP path;
  it does not establish the exact cause of the local-file failure.
  A subsequent [focused KaTeX investigation](katex-investigation.md) reproduced
  the local-file policy restriction and verified rendering through HTTP.
- **Typst:** `~/projects/cv-generator/src/cv.typ` loaded through tinymist with three
  distinct rendered pages. Visual inspection showed typeset content and separate
  page boundaries. The existing plugin's partial-rendering path also worked.
- **Live Typst integration:** an isolated headless Neovim using the installed plugin
  sent an unsaved extra page. The frontend received incremental `diff-v1` messages.
  An editor cursor request produced frontend `jump` messages and showed the added
  heading; a programmatic preview click delivered two source-navigation events
  to the isolated editor. Normal interactive keyboard/mouse behavior still needs review.
- **Source preservation:** the unsaved buffer was restored, the isolated editor
  stopped, and the CV source hash remained unchanged across the update test. The
  CV repository was clean. No live Neovim/Sioyek/Niri configuration was changed.
- **Wikipedia:** rendered and allowed ordinary navigation/scrolling during inspection.
- **Scholar:** redirected to Google's unusual-traffic/CAPTCHA page. No search results
  were verified. The challenge logged storage-access denial and a JavaScript error.
  The cause is unresolved; engine, profile, network/IP and site behavior have not
  been isolated. Firefox fallback remains necessary; no bypass was attempted.

## Scrolling issue and UI correction

The user reported shaking while scrolling Scholar. A suspected cause is the
bottom label allowing long URLs to change the window's minimum width. An experimental
constrained/elided label passed a layout check: switching between short text and
4,096 characters did not change viewport width or minimum window width. This does
**not** prove that the reported Scholar shaking is resolved; an interactive retest
was not completed before code work stopped.

The user's final UI preference is title/tab labels and URL copying, with no passive
URL display, including hover URLs. Experimental code was adjusted and built for that
preference, but the revised GUI/clipboard shortcut has not been checked interactively.

## Lifecycle, diagnostics and security evidence

Application-owned view/loop are released after callbacks are disconnected.
Owned session/display are auto-released afterward. Borrowed WPE view/toplevel
are never unreferenced by the application. Coalesced diagnostic idle callbacks
and Unix signal sources are removed before stack callback state expires.

Compositor close and SIGINT raw results: `runs/compositor-close.*`, `runs/sigint.*`.
Every fresh/warm measurement tests SIGTERM separately. Records include PID/start
identity, all descendant/session members (including bubblewrap and D-Bus proxy),
exit code and survivor inspection over up to 10 seconds. No tracked persistent
leftovers means pass. The transient sandbox denial and rejected preliminary
benchmark runs are disclosed, not accepted as runtime measurements.

Final log audit excluded one fixture run with transient geometry despite equal
sampled endpoints. A stronger post-completion geometry guard now rejects this;
the replacement fixture run and other retained logs satisfy it. One attempted
replacement with a second navigation was also correctly rejected and excluded.
See measurements for preserved artifacts and final values.

Opt-in diagnostics omit all navigation URI strings, error text, cookies and
input contents; report error domain/code only. Load-finished after a failed
navigation is explicitly labelled failed and cannot count as a healthy page.
The post-load crash negative control intentionally kills only this launch's
web process: `runs/crash-negative-control.*` reports abnormal termination,
**fail**, no accepted PSS samples and no survivors. That is a successful test
of the runner's rejection behavior, not a passing browser workload.

Missing trusted file negative control (`runs/missing-local-file.*`) emits
`load-failed phase=0 domain=g-io-error-quark code=1` and
`load-finished status=failed`, without path/query text. WebKit then loads its
default error page; the runner still rejects the earlier failure and collects
no PSS. Root exits 0 and all tracked processes disappear. This is a passing
failure-diagnostic control with an intentionally failed page load.

Repeated warnings: accessibility bus activation fails because `org.a11y.Bus`
is masked; sandboxed web process cannot connect to the a11y bus. Left system
configuration unchanged. No compositor/render/load crash was observed during
accepted runs. Full permission/TLS threat tests belong to later milestones.

Raw runtime metadata shows the WPE web process with `NoNewPrivs: 1`,
`Seccomp: 2`, and distinct mount/PID/user/network namespaces under bubblewrap.
Network/UI processes do not show the same confinement in this stock build.
This documents the observed web-process confinement, not a full sandbox audit.

## Native Wayland, graphics and display limitations

`WPEDisplayWayland` is constructed directly; runtime reports that exact type.
Kernel `7.2.9-arch1-1`, niri `26.04-1`, Mesa `1:26.2.4-1`; one built-in
output, 1920×1200 physical pixels, logical scale 1.0. Benchmark viewport:
950×1188 logical pixels at scale 1.0 (must agree across all retained samples).

WPE web process opens `/dev/dri/renderD128` and `/dev/dri/card1`; Mesa EGL,
GLES and GBM libraries are mapped. This supports a hardware graphics path,
but did not initially establish GPU execution. Subsequent
[blank diagnosis](blank-memory.md) records nonzero amdgpu graphics/compute
execution counters for the web process in all three launches. Hardware GPU
participation is now confirmed for blank; exact GL renderer string and
per-feature/every-frame acceleration remain unmeasured.
No diagnostic packages were installed. Multi-monitor movement/fractional scaling
were unavailable and **not tested**; no display/power/lid/idle settings changed.

## Implementation

- Create/reuse `m0-m1`; save the plan first. C23, four-space indentation,
  Meson `debugoptimized`, warning level 3; initially one source file.
- M0: Meson skeleton requiring installed WPE/WebKit/platform/Wayland modules;
  compile/link public view/lifecycle symbols. Build/run notes, ignored outputs,
  explicit license deferral to the maintainer.
- M1 CLI: `foob [URI]`, default `about:blank`. Accept one explicit HTTP(S),
  absolute `file:` URI or `about:blank`; reject extra arguments/other schemes.
  Full navigation policy is M2.
- Explicit native Wayland display, one web view, explicit ephemeral network
  session, GLib loop. WPE owns rendering, native surfaces and compositor sizing.
- Quit on WPE view `closed`; SIGINT/SIGTERM orderly cleanup, cancel diagnostics,
  release owned objects, check child-process cleanup.
- Opt-in `FOOB_DIAGNOSTICS=1`: load completion/failure, viewport/scale/state,
  process termination, elapsed navigation time. No input contents, cookies or
  sensitive URL queries.
- Trusted local responsive geometry/input/link/scroll/JS/hand-written MathML
  fixtures. No converters, KaTeX, persistent profiles, browser shortcuts, IPC,
  custom engine or M2 work.
- Use [the WPEPlatform integration model](https://wpewebkit.org/blog/2026-10-06-wpe-platform.html).

## Validation and interaction

- Fresh configure/build/link, repeat after final source changes.
- Separate compositor-close and SIGTERM checks; application and tracked browser
  descendants must exit. Persistent leftovers fail.
- Guided user resize/typing/link/scroll/maximize/fullscreen checks; compare visible
  geometry and viewport/input positions.
- Native Wayland proof and available graphics acceleration evidence; insufficient
  evidence means acceleration unverified.
- Memory: blank, trusted fixture, Wikipedia at same actual viewport/scale;
  three independent launches each; three total-process-tree PSS samples one
  second apart starting ten seconds after load completion.
- Warm reload separately; label fresh-process/warm accurately, OS caches
  uncontrolled. Navigation completion is not first-visible-frame timing.
- Attempt simple MathML/JS and one deliberate Scholar exploration. Leave
  challenges to the user; no automated solving or repeated search loop.
- Unavailable multi-monitor/fractional scale explicitly recorded. Capture only
  relevant test windows, delete transient screenshots after inspection.
- Complete independent work while user is away, save interactive checklist.
  Leave idle/lid/power/desktop config unchanged; no input-automation installs.

## Independent review while waiting

Once implementation stabilizes, spawn one fresh-context, read-only reviewer.
Supply the four documents, implementation revision and evidence. Review actual
C23 flags/no silent fallback, valid application-owned C23, compiler extensions,
GLib cleanup macro allowance, GCC warnings, ownership/borrowed references,
async lifetimes, signal cleanup, installed public APIs and milestone boundaries.
Do not claim an extension-free build. Reviewer makes no edits and cannot approve
Gate A. Save `docs/validation/c23-review.md`; fix actionable findings, rerun checks,
request focused follow-up if needed. Review does not replace runtime/user tests.

## Evidence, commits and stop conditions

Record pass/fail/not tested, commands, versions, fixture checksums, measurements
and limitations in `docs/validation/`. Keep a handoff with revision, done/pending
tasks, review findings, issues and next action. Separate M0/M1 commits with
evidence; no credentials/profiles/build outputs/unrelated screenshots.

M0 closes when all M0 P0 build/toolchain checks pass; license is P1 deferred.
M1 is ready for Gate A only when all P0 checks, including interaction, pass and
blocking review findings are resolved. Otherwise mark M1 incomplete and leave a
resumable checkpoint after independent work. Stop before M2; only the maintainer
approves Gate A.
